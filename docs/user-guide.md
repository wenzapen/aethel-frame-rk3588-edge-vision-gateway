# 用户手册

面向日常使用者（值班、配置员、集成商）。界面提供中文 / 英文两种语言，术语一一对应。

---

## 1. 五分钟上手

1. 浏览器打开 `https://<设备IP>:8443`，用 `admin` / 安装时改好的密码登录；
2. 「配置」→ **ONVIF 搜索** → 勾选视频流 → 填摄像机账号 → 添加；
3. 回「监视」页，画面应在 2 秒内出现（首屏只等一页的时间）；
4. 「配置 → AI 分析」打开该通道的 **启用 AI 智能分析**，勾选业务（如区域入侵/越线）与**检测对象**类别；
5. 「告警」页看事件，「录像」页看片段与抓拍。

---

## 2. 登录与账号

- 初始账号 **`admin` / `Aegis@12345`**（安装文档里的公开默认口令），**首次登录强制改密**。
- 忘记密码：在设备主机上删除 `/etc/aethel-frame/users.json` 后重启服务，会按模板重建初始账号
  （所有账号会丢，需要重新建用户；**录像与事件不受影响**）。
- 多用户与权限：「系统」页管理账号，按**能力位**授权（查看事件、确认事件、控制录像、系统运维、编辑配置等）。
  没有对应能力时，按钮直接隐藏，而不是点了报错。

---

## 3. 监视墙（首页）

**顶栏一排状态胶囊**：CPU / 温度 / 内存 / NPU / 磁盘（鼠标悬停有解释；CPU 按单核归一，多核负载可超过 100%）。
窄屏只显示 CPU 与温度。完整指标与趋势曲线在「系统 → 运行态势」。

### 3.1 布局与翻页

| 档位 | 说明 |
|---|---|
| **自适应**（默认） | 按窗口宽度自动 1–4 列（每格最小 320 px） |
| **4 列 / 3 列 / 2 列** | 一行几格；12 路建议 4 列两行 |
| **单列** | 一行 1 格、全宽**主码流**（看细节时用） |

- **一页 = 列数 × 行数**。翻页用画面两侧的 `‹ ›` 圆钮、鼠标滚轮，或点中间的小圆点跳页；中间显示 `第 x/y 页`。
- **一路一个常驻播放器**：切布局、翻页、搜索只改变播放器位置，不销毁重建 ⇒ **来回翻页不断流、不黑屏**。
  ⚠️ 代价：同时打开的路数 = **通道总数**（不是同屏格子数）。12 路以上若整体变卡，
  先关掉不必长期看的路，或用更小的布局档位。
- 宫格档走**子码流**（省带宽、省解码）；单列档自动切**主码流**，主码流不可用时自动回落子码流。
- 搜索框按通道号 / 名称过滤，只影响显示；搜索后自动回第 1 页。
- 画面上下左右居中，末页不满一行也不会堆在左上。

### 3.2 放大与快捷键

- **双击画面 = 放大**：复用当前会话立即显示（不断流），随后主码流首帧到达再淡入清晰版。
- 放大态下 **← / →** 切换上一路 / 下一路；**Esc** 先关告警抽屉、再关放大层。
- 鼠标悬停在格子上出现操作条：抓拍、开始/停止录像、放大。

### 3.3 告警抽屉

左栏「最近告警」点任意一条 → 右侧抽屉：抓拍缩略图、事件字段、**确认**按钮。
抓拍已过保留期时抽屉会明示，不打断操作。

## 4. 通道配置

### 4.1 ONVIF 一键搜索（推荐）

「配置」→ 工具栏 **ONVIF 搜索** → 自动发现当前网段的摄像机 → 勾选目标**视频流**（一台机可能有多条）
→ 填用户名/口令 → 添加。地址与编码参数自动带入，不用手抄 RTSP。

### 4.2 手动新增 / 编辑

- RTSP 地址建议：**子码流做 AI 分析**，主码流看细节。示例
  `rtsp://user:pass@<摄像机IP>:554/Streaming/Channels/101`
- **通道名最多 40 个字符**（中文按 1 个字算）；ONVIF 带回的长名字会自动截断加 `…`。
- 主、子码流都必须是 **H.264 Baseline（无 B 帧）**，否则浏览器预览不出画面。
- 密码里含 `@` `:` 等字符需要 URL 编码。
- 改**源地址 / 编码参数**会重建该路（几秒内画面短暂中断）；只改名称、ROI、业务参数不会重建。
- 列表里 **AI 列的"开/关"是生效值**：总闸关着的路显示 `关`；**一个检测目标都没勾的路也显示 `关`**
  （鼠标悬停可看原因）。
- 掉帧计数在「系统 → 运行态势」的通道矩阵里（大于 0 显示黄字），列表页只保留帧率 / 码率。

## 5. AI 分析（业务与检测对象）

- 「配置 → AI 分析」按通道启用业务：**区域入侵、越线（进出方向）、人群聚集、安全帽**等。
- **总闸**：每路有「启用 AI 智能分析」开关；全局也有总闸，关掉即全设备不推理（画面与录像不受影响）。
- **检测对象 = 该通道各启用业务勾选类别的并集**：
  - 只勾「汽车」就只检汽车 —— 画面里**不会再出现"人"的框**，也不会给人告警；
  - 一个都不勾 = 这路等效关闭（不推理、不画框）。
- ⚠️ **类别名必须能在模型词表里找到**（大小写、拼写、换模型后没重新选类别都算找不到）。
  若某路勾的类别全部不在词表内，这一路会**一个目标都不出**，并在设备日志里打
  `y8_filter WARN tokens_unmatched=...` 或 `y8_filter WARN whitelist_empty ... action=no_detections`。
  正确做法：在「配置 → AI 分析」的**检测对象**多选里重新选（列表来自该模型的词表，不会让你手写错名）。
- ROI / 越线在画面上直接画：点出顶点，双击或回车闭合。
- 每个业务都有「持续多久才报警」的去抖时间，默认偏保守，现场可按需调小。
- 类别按**该通道所用模型的词表**解析：例如客户自带的 2 类模型里 `helmet` 是第 1 类，
  配置里只写类名，保存时后端自动重绑类别编号。

## 6. 告警与取证

- 「告警」页：按时间 / 通道 / 业务 / 是否已确认筛选（服务端分页）；新事件实时推送并在导航上计数。
- **确认**支持单条与批量；**CSV 导出**当前筛选结果；**删除**事件需要「控制录像」级权限。
- 事件字段口径统一为 `aegis.event.v1`（事件号、通道、规则、置信度、时间戳、证据地址）。
- 抓拍存在 `/data/aegis/snapshots`，按配置的保留期自动清理。

---

## 7. 录像与回放

| 方式 | 怎么开 | 说明 |
|---|---|---|
| 连续录像 | 配置里 `record.enable=true`，或「录像」页按通道开关 | 按天数 / 容量配额自动清理 |
| 事件录像 | 业务触发时自动 | 事件前后若干秒 + 抓拍 |
| 手动片段 | 监视墙格子上的「开始 / 停止录像」 | 不限时长，点停止才封口 |

- 「录像」页有两个子页签：**录像**（索引回放，支持跨分段续播）/ **抓拍**（缩略图 → 大图 / 下载 / 删除）。
- 片段是标准 MP4（H.264），可直接下载；回放取流带鉴权，不是裸链接。
- 录像盘建议独立分区（默认 `/data/aegis`），不要和系统盘共用。

## 8. 模型中心

页面分两栏：**内置模型**（随安装包分发）与**自定义模型**（客户自带）。

| | 内置模型 | 自定义模型 |
|---|---|---|
| 位置 | `/opt/aethel-frame/models/builtin/`（只读） | 页面上传 → `/var/lib/aethel-frame/models/`（可写，升级不覆盖） |
| 类名 | 随模型自带 | **上传时必须声明**（`.rknn` 里只有类别数量，没有类名） |
| 删除 | 不允许 | 允许；被通道或模型档案引用时拒绝（提示占用） |

上传四步：选 `.rknn` → 向导自动解析输入尺寸 / 类别数 → 选模型家族 + 绑定类名清单（一行一类，顺序即类别编号）
+ 声明许可来源 → 上传成功后立刻可在「配置 → AI 分析」里选用。

支持的模型家族（白名单）：**YOLOX、YOLOv8、YOLO26**；`PP-YOLOE` 规划在后续版本；**YOLOv5 不支持**
（锚框 + objectness 与现有解码头差异过大，明确拒绝而不是"暂不支持"）。
每条通道**只允许 1 个检测器**（可另加少量二级识别器）。模型许可与分发边界见 [合规声明](compliance.md)。

## 9. 系统页

- **运行态势**：CPU / 内存 / 文件句柄 / 磁盘压力、NPU 利用率与温度、逐通道延迟（抓帧→推理→画框→编码）与趋势曲线、通道矩阵。
- **运行模式**（客户现场可直接切）：
  - `capacity`（默认）：多路优先，追求吞吐与稳定；
  - `performance`：少路低延时。
  切换为**管线级热切换**：进程不退出，顶栏徽标与「当前生效」在 2 秒内自动更新。
- **日志**：页内查看与下载；文件在 `/var/log/aethel-frame/aethel-frame.log`（10 MB × 5 份滚动）。
- **授权**：状态、路数上限、已用路数、到期日、设备码、导入 License。详见 [授权说明](licensing.md)。

## 10. 外部集成

| 出口 | 用途 | 注意 |
|---|---|---|
| MQTT | 事件推送到 broker | 一条事件最多两条消息（告警 + 媒体）；**同时只允许 1 个 MQTT 出口** |
| Webhook / HTTP | 事件 JSON 与图片/视频推给第三方平台 | 媒体上传目标为 S3/MinIO 兼容存储 |
| MinIO / S3 | 证据（抓拍、片段）备份 | Access Key / Secret Key 是账号密码（不是桶名）；启用前必须填地址、桶、读 URL 模板 |

默认全部关闭。启用前先在「集成」页点**测试连接**。字段口径与告警页一致（`aegis.event.v1`），
便于 MES / 工单 / 平台侧对同一事件做关联。

## 11. 命令行

```bash
aethel-frame --version                 # 版本与构建信息
aethel-frame --machine-info            # 打印设备码 JSON（买授权时发给厂商）
aethel-frame --check-config --config <文件>   # 只校验配置，不起任何流
aethel-frame --config <文件> --mode capacity|performance   # 手工前台运行（调试/演示）
sudo aegis-activate-profile 8          # 扩到 8 路（合并不覆盖，见安装指南）
```

## 12. 容量与性能建议

| 路数 | 内存 | CPU 实测（AI + 录像 + 预览全开） | 备注 |
|---|---|---|---|
| 2–4 | ≥ 4 GB | 约 1–1.5 核 | 免费档 2 路 |
| 8 | ≥ 8 GB | 约 2.2 核 | 建议 4 列布局 |
| 12 | ≥ 8 GB + 8 核 | 约 3.7–4.0 核 | **录像单独一块盘**；帧率满额、无丢帧 |

- 想再省 CPU：关掉不看的浏览器页（每开一路就有一个常驻播放器）、用子码流做分析、降低预览帧率。
- 画面延迟主要取决于**摄像机码流的 GOP 与帧率**，不是本设备；建议 GOP 1–2 秒、分析路 12–15 fps。

## 13. 常见问题

| 现象 | 处理 |
|---|---|
| 登录后进不去 / 一直转圈 | 确认访问的是 `https://`，且证书告警已选择继续；换 Chrome/Edge 最新版 |
| 某路一直 `reconnecting` | 先用 VLC/ffprobe 在同网段验证 RTSP；检查密码特殊字符是否 URL 编码 |
| 画面上没有框，但 AI 显示"开" | 检查**检测对象**是否勾了类别、类别名是否在模型词表内（见 §5 的警告） |
| 换了自带模型后不报警 | 新模型词表与旧业务勾选的类别名不一致 ⇒ 重新选类别 |
| 浏览器黑屏但设备端录像正常 | 码流不是 H.264 Baseline（有 B 帧） |
| 翻页时画面中断 | 确认没在浏览器里禁用来路连接；单列/放大与宫格是两个独立会话，正常各占一路 |
| 想启用第 3 路被拒 | 免费档只有 2 路，见 [授权说明](licensing.md) |
