# 用户手册

本手册面向日常使用者（值班人员、配置人员、系统集成商）。界面提供中文 / 英文两种语言，术语一一对应。

---

## 1. 快速开始

1. 浏览器打开 `https://<设备IP>:8443`，用 `admin` / 安装时改好的密码登录；
2. 「配置」→ **ONVIF 搜索** → 勾选视频流 → 填摄像机账号 → 添加；
3. 回到「监视」页，画面应在 2 秒内出现（首屏只加载当前一页）；
4. 「配置 → AI 分析」打开该通道的 **启用 AI 智能分析**，勾选业务（如区域入侵/越线）与**检测对象**类别；
5. 「告警」页看事件，「录像」页看片段与抓拍。

---

## 2. 登录与账号

- 初始账号 **`admin` / `Aegis@12345`**（安装文档里的公开默认口令），**首次登录强制改密**。
- 忘记密码：在设备主机上删除 `~/aethel-frame/etc/users.json` 后重启服务（`systemctl --user restart aethel-frame`），
  会按模板重建初始账号（所有账号会丢，需要重新建用户；**录像与事件不受影响**）。
- 多用户与权限：「系统」页管理账号，内置**管理员 / 工程师 / 操作员**三种角色，具体权限按**能力位**授权
  （查看事件、确认事件、控制录像、系统运维、编辑配置等）。
  没有对应能力时，按钮直接隐藏，而不是点了报错。

## 3. 监视墙（首页）

**顶栏一排状态胶囊**：CPU / 温度 / 内存 / NPU / 磁盘（鼠标悬停有解释；CPU 按单核归一，多核负载可超过 100%）。
窄屏只显示 CPU 与温度。完整指标与趋势曲线在「系统 → 运行态势」。

### 3.1 布局与翻页

| 档位 | 说明 |
|---|---|
| **自适应**（默认） | 按窗口宽度自动 1–4 列（每格最小 320 px） |
| **4 列 / 3 列 / 2 列** | 一行几格；12 路建议 4 列两行 |
| **单列** | 一行 1 格、全宽**主码流**（看细节时用） |

- **一页 = 列数 × 行数**。翻页用画面两侧的 `‹ ›` 圆钮、鼠标滚轮，或点中间的小圆点跳页；中间显示 `第 x/y 页`。
- **一路一个常驻播放器**：切布局、翻页、搜索只改变播放器位置，不销毁重建 ⇒ **来回翻页不断流、不黑屏**。
  ⚠️ 代价：同时打开的路数 = **通道总数**（不是同屏格子数）。12 路以上若出现整体卡顿，
  先关闭无需长时间查看的路，或用更小的布局档位。
- 宫格档走**子码流**（省带宽、省解码）；单列档自动切**主码流**，主码流不可用时自动回落子码流。
- 搜索框按通道号 / 名称过滤，只影响显示；搜索后自动回第 1 页。
- 画面上下左右居中，末页不满一行也不会堆在左上。

### 3.2 放大与快捷键

- **双击画面 = 放大**：复用当前会话立即显示（不断流），随后主码流首帧到达再淡入清晰版。
- 放大态下 **← / →** 切换上一路 / 下一路；**Esc** 先关告警抽屉、再关放大层。
- 鼠标悬停在格子上出现操作条：抓拍、开始/停止录像、放大。

### 3.3 告警抽屉

左栏「最近告警」点任意一条 → 右侧抽屉：抓拍缩略图、事件字段、**确认**按钮。
抓拍已过保留期时抽屉会明示，不打断操作。

## 4. 通道配置

### 4.1 ONVIF 一键搜索（推荐）

「配置」→ 工具栏 **ONVIF 搜索** → 自动发现当前网段的摄像机 → 勾选目标**视频流**（一台机可能有多条）
→ 填用户名/口令 → 添加。地址与编码参数自动带入，不用手抄 RTSP。

多台摄像机账号不同也不用逐台手填：设备可保存一组常用凭据，搜索到设备后**自动逐套尝试**取流，
命中的那套会记在该设备上；凭据列表始终掩码显示，口令不回显。

### 4.2 手动新增 / 编辑

- RTSP 地址建议：**子码流做 AI 分析**，主码流看细节。示例
  `rtsp://user:pass@<摄像机IP>:554/Streaming/Channels/101`
- **通道名最多 40 个字符**（中文按 1 个字算）；ONVIF 带回的长名字会自动截断加 `…`。
- 编码格式不限：H.264 或 H.265 都可以（由本设备硬件解码）；**浏览器看到的画面是本设备重新编码输出的**，
  与摄像机码流的 profile / 有无 B 帧无关。
- 密码里含 `@` `:` 等字符需要 URL 编码。
- 改**源地址 / 编码参数**会重建该路（画面中断约 1 秒后自动恢复）；只改名称、ROI、业务参数不会重建。
- **停止会写进配置**：点某路「停止」不只停当前画面，还会把这一路标记为“下次启动不随网关自动播放”（状态列出现
  `已停用 · 重启不播放` 徽标）；随时再点「启动」即可恢复，恢复时会重新写回“随网关播放”。
- **AI 列的“开 / 关”就是这一路推理开关的当前值**：点按钮后列**立即跟着变**；开关虽然开着、但此刻不真正检测
  （全局总闸关着 / 一个检测目标都没勾）时，列旁显示黄色小字 `未生效`（鼠标悬停可看原因）。
- 操作列里有并排的 **开AI / 关AI** 两颗按钮（当前态高亮、重复点置灰）：它热切推理开关，**画面 / 录像不断、不重建管线**；
  还没在「AI 分析」页挂上模型的路，两颗都置灰。
- 勾选多路后顶部出现**批量条**：统一启动 / 统一停止 / 统一重启、统一开 AI / 统一关 AI、以及 **AI 模板批量下发**。
  下发前会先列出逐路计划（哪几路执行、哪几路跳过及原因），允许部分成功；已在目标态或正在重建的路会自动跳过。
- 掉帧计数在「系统 → 运行态势」的通道矩阵里（大于 0 显示黄字），列表页只保留帧率 / 码率。
- **断流自动恢复**：摄像机断流或网络抖动后，该路会自动重连——先快速重试（间隔从 2 秒起逐次加长，最长 30 秒）；
  快速重试次数用尽后转为**定间隔（默认约 60 秒）持续重试，直到画面恢复前不会停止、无需人工干预**，
  重新出帧后重试计数自动复位。期间状态列显示 `reconnecting`，属正常行为。

## 5. AI 分析（业务与检测对象）

- 「配置 → AI 分析」按通道启用业务：**区域入侵、越线（进出方向）、人群聚集、安全帽**等。
- **总闸**：每路有「启用 AI 智能分析」开关；全局也有总闸，关掉即全设备不推理（画面与录像不受影响）。
- **检测对象 = 该通道各启用业务勾选类别的并集**：
  - 只勾「汽车」就只检汽车 —— 画面里**不会再出现"人"的框**，也不会给人告警；
  - 一个都不勾 = 这路等效关闭（不推理、不画框）。
- ⚠️ **类别名必须能在模型词表里找到**（大小写、拼写、换模型后没重新选类别都算找不到）。
  若某路勾的类别全部不在词表内，这一路会**一个目标都不出**（画面上没有框，也不会有告警）。
  正确做法：在「配置 → AI 分析」的**检测对象**多选里重新选（列表来自该模型的词表，不会让你手写错名）。
- ROI / 越线在画面上直接画：点出顶点，双击或回车闭合。
- 每个业务都有「持续多久才报警」的去抖时间，默认偏保守，现场可按需调小。
- 类别按**该通道所用模型的词表**解析：例如客户自带的 2 类模型里 `helmet` 是第 1 类，
  配置里只写类名，保存时后端自动重绑类别编号。
- **保存入口只有一个「保存并生效」**：在该页换模型、改业务、改抽帧频率都只改草稿，点一次「保存并生效」
  把它们一次性下发、**只重建一次**（不会因为换模型与保存业务各重建一次）。

### 5.1 AI 模板（可复用的配置快照）

模板 = 模型 + 灵敏度 + 抽帧频率 + 业务配置的一份可复用快照。**模板不携带“这一路是否开启 AI”这个总闸**
（加载 / 保存模板都不会改动本路的启用状态），模板也不是强制的（新增视频流默认不绑定任何模板）。
三项操作相互独立，交互仿照 Windows 的“打开 / 另存为”对话框：

- **加载模板**：弹出模板清单，选中一份点「加载」——模板内容填进下方配置（**不立即生效**，可再改几个参数），
  同时把本路引用的模板切为它（只改引用标记，不重建）；点「保存并生效」才真正落到本路。
- **保存为模板**：选一个现有模板 = 用当前配置**覆盖**它（若它已被其它路引用，弹窗会提示“引用它的 N 路会在保存时
  一并应用新配置”，保存时当场自动下发）；输入新名称 = **另存为新模板**（不覆盖任何人，本路引用随即切到它）。
- **保存并生效**：只落本路配置，**不碰模板**（模板的去向只在模板弹窗里显式决定）。
- **批量下发**：在「配置」页勾选多路 → **AI 模板批量下发** → 选模板，逐路应用并**同时完成绑定**（每路重建一次）。
  想让某路“受该模板批量管理”，用它绑定一次即可；未绑定的路不受后续批量下发影响。

## 6. 告警与取证

- 「告警」页：按时间 / 通道 / 业务 / 是否已确认筛选（服务端分页）；新事件实时推送并在导航上计数。
- **确认**支持单条与批量；**CSV 导出**当前筛选结果；**删除**事件需要「控制录像」级权限。
- 事件字段口径统一为 `aegis.event.v1`（事件号、通道、规则、置信度、时间戳、证据地址）。
- 抓拍存在 `~/aethel-frame/data/snapshots`，按配置的保留期自动清理。

## 7. 录像与回放

| 方式 | 怎么开 | 说明 |
|---|---|---|
| 连续录像 | 配置里 `record.enable=true`，或「录像」页按通道开关 | 按天数 / 容量配额自动清理 |
| 事件录像（智能录像） | 「录像 → 录制管理」按通道开启智能录像开关 | 常驻缓冲持续缓存画面，事件触发时**事件发生之前的画面也在片段里**：事件前默认 10 秒（可配 1–30）+ 事件后默认 10 秒（可配 1–60），片头从关键帧开始、不花屏；预录段可从事件详情回放 |
| 手动片段 | 监视墙格子上的「开始 / 停止录像」 | 不限时长，点「停止」才结束当前片段 |

- 「录像」页有三个子页签，默认落在**录制管理**（控制/配置）：**录制管理**（智能录像开关与手动录像，按“一行 2 路”）
  / **回放**（索引回放，支持跳分段续播）/ **抓拍**（缩略图 → 大图 / 下载 / 删除）；从格子菜单的“最近录像”点进来会直接进回放。
- 片段是标准 MP4（H.264），可直接下载；回放取流带鉴权，不是裸链接。
- 录像盘建议独立分区/独立盘（默认在 `~/aethel-frame/data`；要存很多天请把配置项 `record.path` 指到挂载点）。

## 8. 模型中心

页面分两栏：**内置模型**（随安装包分发）与**自定义模型**（客户自带）。

| | 内置模型 | 自定义模型 |
|---|---|---|
| 位置 | `/opt/aethel-frame/models/builtin/`（只读） | 页面上传 → `~/aethel-frame/var/models/`（可写，升级不覆盖） |
| 类名 | 随模型自带 | **上传时必须声明**（`.rknn` 里只有类别数量，没有类名） |
| 删除 | 不允许 | 允许；被通道或模型档案引用时拒绝（提示占用） |

上传四步：**选文件 → 声明 → 试跑 → 启用**。选 `.rknn`（单个不超过 64 MiB）→ 向导自动解析输入尺寸 / 类别数，
选模型家族 + 绑定类名清单（一行一类，顺序即类别编号）+ 声明许可来源 →
**试跑验证**：用真实画面跑一次检测，校验声明与权重是否一致（家族选错、类别顺序写错、预处理口径不对都会在这一步暴露）；
试跑在独立进程完成，不影响正在运行的通道 → 报告通过后启用，即可在「配置 → AI 分析」里选用。
声明改了旧试跑报告作废，需重新试跑。

支持的模型家族（白名单）：**YOLOX、YOLOv8、YOLO26**；`PP-YOLOE` 规划在后续版本；**YOLOv5 不支持**（明确拒绝，而非"暂不支持"）。
每条通道**只允许 1 个检测器**（可另加少量二级识别器）。模型许可与分发边界见 [合规声明](compliance.md)。

## 9. 系统页

页面拆为四个页签：**运行态势 / 时延分析 / 存储与资源 / 授权与模式**（顶部健康条常驻页签上方，切页签不丢状态）。

- **运行态势**：CPU / 内存 / 文件句柄 / 磁盘压力、NPU 利用率与温度、逐通道延迟（抓帧→推理→画框→编码）与趋势曲线、通道矩阵。
- **运行模式**（客户现场可直接切）：
  - `capacity`（默认）：多路优先，追求吞吐与稳定；
  - `performance`：少路低延时。
  切换后 **2 秒内生效，服务不重启**；顶栏徽标与「当前生效」同步更新。
- **日志**：页内查看与下载；导出整包日志时逐行脱敏（口令/密钥不会出现明文）；文件在 `~/aethel-frame/logs/aethel-frame.log`（10 MB × 5 份滚动）。
- **崩溃诊断**：页面提供崩溃产物入口，异常退出时的诊断包可在线查看 / 下载，不必登设备翻目录。
- **授权**：状态、路数上限、已用路数、到期日、机器信息、上传 License。详见 [授权说明](licensing.md)。

## 10. 外部集成

「集成」页分两个页签：**媒体服务器 / 消息队列**。

| 出口 | 用途 | 注意 |
|---|---|---|
| MQTT | 事件推送到 broker | 一条事件最多两条消息（告警 + 媒体）；**同时只允许 1 个 MQTT 出口** |
| Webhook / HTTP | 事件 JSON 与图片/视频推给第三方平台 | 媒体上传目标为 S3/MinIO 兼容存储 |
| MinIO / S3 | 证据（抓拍、片段）备份 | Access Key / Secret Key 是账号密码（不是桶名）；启用前必须填地址、桶、读 URL 模板 |

默认全部关闭。启用前先在「集成」页点**测试连接**。字段口径与告警页一致（`aegis.event.v1`），
便于 MES / 工单 / 平台侧对同一事件做关联。

## 11. 命令行

```bash
aethel-frame --version                 # 版本与构建信息
aethel-frame --machine-info            # 打印设备码 JSON（买授权时发给厂商）
aethel-frame --check-config --config <文件>   # 只校验配置，不起任何流
aethel-frame --config <文件> --mode capacity|performance   # 手工前台运行（调试/演示）
```

> 扩容/缩容没有命令行工具：导入更高档的 `license.dat` 即时生效，视频源在 Web 「配置」页加/删（见安装指南 §6）。

## 12. 容量与性能建议

| 路数 | 内存 | CPU 实测（AI + 录像 + 预览全开） | 备注 |
|---|---|---|---|
| 2–4 | ≥ 4 GB | 约 1–1.5 核 | 免费档 2 路 |
| 8 | ≥ 8 GB | 约 2.2 核 | 建议 4 列布局 |
| 12 | ≥ 8 GB | 约 3.7–4.0 核 | **录像单独一块盘**；帧率满额、无丢帧 |

- 若需进一步降低 CPU 占用：关闭不再查看的浏览器页（每打开一路就有一个常驻播放器）、用子码流做分析、降低预览帧率。
- 画面延迟主要取决于**摄像机码流的 GOP 与帧率**，不是本设备；建议 GOP 1–2 秒、分析路 12–15 fps。

## 13. 常见问题

| 现象 | 处理 |
|---|---|
| 登录后无法进入 / 持续加载 | 确认访问的是 `https://`，且已对证书告警选择继续；改用 Chrome/Edge 最新版 |
| 某路一直 `reconnecting` | 设备会在后台持续自动重试（见 §4.2 “断流自动恢复”），无需人工干预；先用 VLC/ffprobe 在同网段验证 RTSP 可拉，检查密码特殊字符是否 URL 编码；源头恢复后画面自行回来 |
| 画面上没有框，但 AI 显示"开" | 检查**检测对象**是否勾了类别、类别名是否在模型词表内（见 §5 的警告） |
| 换了自带模型后不报警 | 新模型词表与旧业务勾选的类别名不一致 ⇒ 重新选类别 |
| 浏览器黑屏但设备端录像正常 | 该路是否处于运行中、预览走的子码流是否正常（宫格预览走子码流，见 §3.1）；在「配置」页确认该路已启动，必要时点「重启」 |
| 翻页时画面中断 | 确认浏览器未限制同时连接数；单列/放大与宫格是两个独立会话，正常各占一路 |
| 启用第 3 路被拒绝 | 免费档仅有 2 路，见 [授权说明](licensing.md) |
