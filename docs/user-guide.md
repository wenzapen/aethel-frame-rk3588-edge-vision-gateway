# 用户手册

本手册面向日常使用者（值班人员、配置人员、系统集成商）。界面提供中文 / 英文两种语言，术语一一对应。

---

## 1. 快速开始

1. 浏览器打开 `https://<设备IP>:8443`，用 `admin` / 安装时改好的密码登录；
2. 「配置」→ **ONVIF 搜索** → 勾选视频流 → 填摄像机账号 → 添加；
3. 回到「监视」页，画面应在 2 秒内出现（首屏只加载当前一页）；
4. 「配置 → AI 分析」打开该通道的 **启用 AI 智能分析**，勾选业务（如区域入侵/越线）与**检测对象**类别；
5. 「告警」页看事件，「录像」页看片段与抓拍。

---

## 2. 登录与账号

- 初始账号 **`admin` / `Aegis@12345`**（安装指南中列明的默认密码），**首次登录强制修改密码**。
- 重置密码：在设备主机上删除 `~/aethel-frame/etc/users.json` 后重启服务（`systemctl --user restart aethel-frame`），
  系统会按模板重建初始账号；**全部自定义账号同时删除**，需要重新创建；录像与事件数据不受影响。
- 多用户与权限：「系统」页管理账号，内置**管理员 / 工程师 / 操作员**三种角色，具体权限按**能力位**授权
  （查看事件、确认事件、控制录像、系统运维、编辑配置等）。
  无对应能力时，相关按钮直接隐藏（而非点击后报错）。

## 3. 监视墙（首页）

**顶栏状态指示**：CPU / 温度 / 内存 / NPU / 磁盘（悬停查看说明；CPU 占用按单核归一，多核负载可超过 100%）。
窄屏只显示 CPU 与温度。完整指标与趋势曲线在「系统 → 运行态势」。

### 3.1 布局与翻页

| 档位 | 说明 |
|---|---|
| **自适应**（默认） | 按窗口宽度自动 1–4 列（每格最小 320 px） |
| **4 列 / 3 列 / 2 列** | 一行几格；12 路建议 4 列两行 |
| **单列** | 一行 1 格、全宽**主码流**（需要查看细节时使用） |

- **一页 = 列数 × 行数**。可通过画面两侧的箭头按钮、鼠标滚轮或底部页码导航翻页；中部显示当前页码（`第 x/y 页`）。
- **一路一个常驻播放器**：切换布局、翻页、搜索只改变播放器位置，不销毁重建，**翻页与布局切换均不中断播放**。
  注意：常驻播放器与**通道总数**一一对应（与同屏格数无关）。通道达到 12 路及以上且出现整体卡顿时，
  请关闭暂未查看的通道或选用更少的布局格数。
- 宫格档使用**子码流**（降低带宽与解码开销）；单列档自动切换**主码流**，主码流不可用时自动回落子码流。
- 搜索框按通道号 / 名称过滤，仅影响显示；搜索后自动回到第 1 页。
- 画面在格子内上下左右居中，末页不满一行时仍居中排布。

### 3.2 放大与快捷键

- **双击画面放大**：复用当前会话立即显示（不中断播放），主码流首帧到达后平滑切换为高清画面。
- 放大态下 **← / →** 切换上一路 / 下一路；**Esc** 先关告警抽屉、再关放大层。
- 鼠标悬停在格子上出现操作条：抓拍、开始/停止录像、放大。

### 3.3 告警抽屉

左栏「最近告警」点任意一条 → 右侧抽屉：抓拍缩略图、事件字段、**确认**按钮。
抓拍已过保留期时，抽屉会明确提示，不影响其余操作。

## 4. 通道配置

### 4.1 ONVIF 一键搜索（推荐）

「配置」→ 工具栏 **ONVIF 搜索** → 自动发现当前网段的摄像机 → 勾选目标**视频流**（一台设备可能包含多条）
→ 填用户名/密码 → 添加。地址与编码参数自动带入，无需手工填写 RTSP 地址。

多台摄像机账号不同时，无需逐台填写：可预先保存一组常用凭据，搜索到设备后系统**自动逐个尝试**取流，
命中的凭据绑定在该设备上；凭据列表始终掩码显示，密码不回显。

### 4.2 手动新增 / 编辑

- RTSP 地址建议：**子码流用于 AI 分析**，主码流用于查看细节。示例
  `rtsp://user:pass@<摄像机IP>:554/Streaming/Channels/101`
- **通道名最多 40 个字符**（中文字符按 1 个计）；ONVIF 带回的超长名称自动截断并加 `…`。
- 与摄像机码流的 profile / 有无 B 帧无关。
- 密码中包含 `@` `:` 等字符时需要 URL 编码。
- **「停止」是持久操作**：停止某路会同时标记该通道在网关重启后不自动启动（状态列出现
  `已停用 · 重启不播放` 徽标）；点击「启动」即可恢复，并回写自动启动标记。
- AI 列的「开 / 关」显示该路推理开关的当前状态，操作后立即刷新；开关已启用但当前不执行推理时
  （全局 AI 开关关闭，或未选择任何检测目标），列旁显示黄色提示 `未生效`（悬停查看原因）。
- 操作列提供 **开AI / 关AI** 两个按钮（当前状态高亮，重复操作置灰）：热切换推理开关，**预览与录像不中断，
  无需重建管线**；尚未绑定模型的通道，两个按钮均置灰。
- 勾选多路后顶部出现**批量条**：统一启动 / 统一停止 / 统一重启、统一开 AI / 统一关 AI、以及 **AI 模板批量下发**。
  下发前会先列出逐路计划（哪几路执行、哪几路跳过及原因），允许部分成功；已在目标态或正在重建的路会自动跳过。
- 掉帧计数显示在「系统 → 运行态势」的通道矩阵中（大于 0 显示黄色）；列表页仅保留帧率 / 码率。
- **断流自动恢复**：摄像机断流或网络抖动后，该路会自动重连——先快速重试（间隔从 2 秒起逐次加长，最长 30 秒）；
  快速重试用尽后转为**定间隔（默认约 60 秒）持续重试，直至画面恢复，无需人工干预**，
  重新出帧后重试计数自动复位。期间状态列显示 `reconnecting`，属正常行为。

## 5. AI 分析（业务与检测对象）

- 「配置 → AI 分析」按通道启用业务：**区域入侵、越线（进出方向）、人群聚集、安全帽**等。
- **总开关**：每路有「启用 AI 智能分析」开关；全局另有统一开关，关闭后全设备停止推理（画面与录像不受影响）。
- **检测对象 = 该通道各启用业务勾选类别的并集**：
  - 仅勾选「汽车」时只检出汽车：画面不显示「人」的检测框，也不产生针对人的告警；
  - 全部不勾选时，该通道等效关闭（不推理、不绘制检测框）。
- ⚠️ **类别名必须与模型词表精确匹配**（区分大小写与拼写；更换模型后未重新选择类别即视为不匹配）。
  若某通道勾选的类别全部不在词表内，该通道将不产生任何检出结果（无检测框、无告警）。
  处理方式：在「配置 → AI 分析」的**检测对象**列表中重新勾选（列表项来自该模型词表，无需手工输入）。
- ROI / 越线在画面上直接绘制：点出顶点，双击或回车闭合。
- 各业务均提供告警延时（去抖）参数：目标持续满足条件超过该时长才触发告警；默认值偏保守，现场可按需调小。
- 类别按**该通道所用模型的词表**解析：例如客户自带的 2 类模型中 `helmet` 是第 1 类，
  配置中只写类名，保存时后端自动重绑类别编号。
- **统一保存入口「保存并生效」**：在该页更换模型、修改业务、调整抽帧频率均先写入草稿；点击一次「保存并生效」
  即一次性下发全部变更，通道**只重建一次**。

### 5.1 AI 模板（可复用的配置快照）

模板 = 模型 + 灵敏度 + 抽帧频率 + 业务配置的可复用快照。**模板不包含 AI 启用开关**（加载 / 保存模板
均不改动本通道的启用状态），且非强制项（新增视频流默认不绑定任何模板）。三项操作相互独立：

- **加载模板**：在模板清单中选中一份点「加载」——模板内容写入下方配置（**不立即生效**，可继续调整参数），
  本通道引用的模板同时切换为该模板（仅更新引用标记，不重建）；点击「保存并生效」后配置才在该通道生效。
- **保存为模板**：选择一个现有模板表示用当前配置**覆盖**它（若该模板已被其他通道引用，界面会提示
  「引用该模板的 N 路将在保存时一并应用新配置」，保存时自动下发）；输入新名称表示**另存为新模板**
  （不覆盖既有模板，本通道引用随即切换为新模板）。
- **保存并生效**：仅保存本通道配置，**不修改模板**（模板的覆盖与新建仅在模板对话框中显式操作）。
- **批量下发**：在「配置」页勾选多路 → **AI 模板批量下发** → 选模板，逐路应用并**同时完成绑定**（每路重建一次）。
  如需某通道受该模板批量管理，使用该模板绑定一次即可；未绑定的通道不受后续批量下发影响。

## 6. 告警与取证

- 「告警」页：按时间 / 通道 / 业务 / 是否已确认筛选（服务端分页）；新事件实时推送并在导航上计数。
- **确认**支持单条与批量；**CSV 导出**当前筛选结果；**删除**事件需要「控制录像」级权限。
- 事件字段口径统一为 `aegis.event.v1`（事件号、通道、规则、置信度、时间戳、证据地址）。
- 抓拍存在 `~/aethel-frame/data/snapshots`，按配置的保留期自动清理。

## 7. 录像与回放

| 方式 | 开启途径 | 说明 |
|---|---|---|
| 连续录像 | 配置项 `record.enable=true`，或「录像」页按通道开关 | 按天数 / 容量配额自动清理 |
| 事件录像（智能录像） | 「录像 → 录制管理」按通道开启智能录像开关 | 持续维护内存缓冲，事件触发时**片段包含事件发生之前的画面**：事件前默认 10 秒（可配 1–30）+ 事件后默认 10 秒（可配 1–60），片头自关键帧起始、画面完整；预录段可在事件详情中回放 |
| 手动片段 | 监视墙格子上的「开始 / 停止录像」 | 不限时长，点「停止」才结束当前片段 |

- 「录像」页有三个子页签，默认落在**录制管理**（启停与配置）：**录制管理**（智能录像开关与手动录像，每行显示 2 路）
  / **回放**（索引回放，支持跨分段续播）/ **抓拍**（缩略图 → 大图 / 下载 / 删除）；从监视墙格子菜单的「最近录像」进入时直达回放页签。
- 片段为标准 MP4（H.264），可直接下载；回放与下载均需鉴权访问，不暴露无鉴权地址。
- 建议使用独立分区或独立磁盘存放录像（默认位于 `~/aethel-frame/data`；需要长时间保存时，将配置项 `record.path` 指向挂载点）。

## 8. 模型中心

页面分两栏：**内置模型**（随安装包分发）与**自定义模型**（客户自带）。

| | 内置模型 | 自定义模型 |
|---|---|---|
| 位置 | `/opt/aethel-frame/models/builtin/`（只读） | 页面上传 → `~/aethel-frame/var/models/`（可写，升级不覆盖） |
| 类名 | 模型自带 | **上传时必须声明**（`.rknn` 中仅含类别数量，无类名） |
| 删除 | 不允许 | 允许；被通道或模型档案引用时拒绝（提示占用） |

上传四步：**选文件 → 声明 → 试跑 → 启用**。选 `.rknn`（单个不超过 64 MiB）→ 向导自动解析输入尺寸 / 类别数，
选模型家族 + 绑定类名清单（一行一类，顺序即类别编号）+ 声明许可来源 →
**试跑验证**：用真实画面执行一次检测，校验声明与权重是否一致（模型家族不符、类别顺序错误、预处理参数不一致均在此环节检出）；
试跑在独立进程完成，不影响正在运行的通道 → 报告通过后启用，即可在「配置 → AI 分析」中选用。
修改声明后既有试跑报告失效，需重新执行试跑。

支持的模型家族：**YOLOX、YOLOv8、YOLO26**；YOLOv5 不在支持范围；`PP-YOLOE` 支持规划于后续版本。
每条通道**仅允许 1 个检测器**（可另加不超过 2 个二级识别器）。模型许可与分发边界见 [合规声明](compliance.md)。

## 9. 系统页

页面拆为四个页签：**运行态势 / 时延分析 / 存储与资源 / 授权与模式**（顶部健康条常驻显示，切换页签不影响其状态）。

- **运行态势**：CPU / 内存 / 文件句柄 / 磁盘压力、NPU 利用率与温度、逐通道延迟（抓帧→推理→画框→编码）与趋势曲线、通道矩阵。
- **运行模式**（客户现场可直接切）：
  - `capacity`（默认）：多路优先，追求吞吐与稳定；
  - `performance`：少路低延时。
  切换后 **2 秒内生效，服务不重启**；顶栏徽标与「当前生效」同步更新。
- **日志**：页内查看与下载；导出整包日志时逐行脱敏（密码、密钥不以明文出现）；文件在 `~/aethel-frame/logs/aethel-frame.log`（10 MB × 5 份滚动）。
- **崩溃诊断**：异常退出产生的诊断包可在页面在线查看与下载，无需登录设备访问文件目录。
- **授权**：状态、路数上限、已用路数、到期日、机器信息、上传 License。详见 [授权说明](licensing.md)。

## 10. 外部集成

「集成」页分两个页签：**媒体服务器 / 消息队列**。

| 出口 | 用途 | 注意 |
|---|---|---|
| MQTT | 事件推送到 broker | 一条事件最多两条消息（告警 + 媒体）；**同时只允许 1 个 MQTT 出口** |
| Webhook / HTTP | 事件 JSON 与图片/视频推给第三方平台 | 媒体上传目标为 S3/MinIO 兼容存储 |
| MinIO / S3 | 证据（抓拍、片段）备份 | Access Key / Secret Key 为存储服务的账号与密钥（非桶名）；启用前需填写地址、桶、只读 URL 模板 |

默认全部关闭。启用前先在「集成」页点**测试连接**。字段口径与告警页一致（`aegis.event.v1`），
便于 MES / 工单 / 平台侧对同一事件做关联。

## 11. 命令行

```bash
aethel-frame --version                 # 版本与构建信息
aethel-frame --machine-info            # 输出设备码 JSON（申请授权时提供给厂商）
aethel-frame --check-config --config <文件>   # 只校验配置，不起任何流
aethel-frame --config <文件> --mode capacity|performance   # 手工前台运行（调试/演示）
```

> 路数扩容与缩容无需命令行工具：导入更高档的 `license.dat` 即时生效；视频源在「配置」页添加或删除（见安装指南 §6）。

## 12. 容量与性能建议

| 路数 | 内存 | CPU 实测（AI + 录像 + 预览全开） | 备注 |
|---|---|---|---|
| 2–4 | ≥ 4 GB | 约 1–1.5 核 | 免费档 2 路 |
| 8 | ≥ 8 GB | 约 2.2 核 | 建议 4 列布局 |
| 12 | ≥ 8 GB | 约 3.7–4.0 核 | **录像单独一块盘**；帧率满额、无丢帧 |

- 若需进一步降低 CPU 占用：关闭不再查看的浏览器页（每个预览通道对应一个常驻播放器）、使用子码流进行分析、降低预览帧率。
- 画面延迟主要取决于**摄像机码流的 GOP 与帧率**，不是本设备；建议 GOP 1–2 秒、分析路 12–15 fps。

## 13. 常见问题

| 现象 | 处理 |
|---|---|
| 登录后无法进入 / 持续加载 | 确认访问的是 `https://`，且已对证书告警选择继续；改用 Chrome/Edge 最新版 |
| 某路一直 `reconnecting` | 设备会在后台持续自动重试（见 §4.2 “断流自动恢复”），无需人工干预；先用 VLC/ffprobe 在同网段验证 RTSP 可拉，检查密码特殊字符是否 URL 编码；源头恢复后画面自行回来 |
| 画面无检测框，但 AI 状态显示「开」 | 检查**检测对象**是否已勾选类别、类别名是否在模型词表内（见 §5 的注意事项） |
| 更换客户自带模型后不产生告警 | 新模型词表与旧业务勾选的类别名不一致 ⇒ 重新选择类别 |
| 浏览器黑屏但设备端录像正常 | 该路是否处于运行中、预览走的子码流是否正常（宫格预览走子码流，见 §3.1）；在「配置」页确认该路已启动，必要时点「重启」 |
| 翻页时画面中断 | 确认浏览器未限制同时连接数；单列/放大与宫格是两个独立会话，正常各占一路 |
| 启用第 3 路被拒绝 | 免费档仅有 2 路，见 [授权说明](licensing.md) |
