逐组件的清单同时写在交付包根目录的 `NOTICE` 里（与本文一致，冲突时以 `NOTICE` 为准）。

## 3. 模型与数据许可（重点）

### 3.1 交付包内置的模型：只有一个，且可自由分发

| 内置模型 | 家族 | 许可 | 可随包分发 |
|---|---|---|---|
| **YOLOX-S / COCO（80 类）** | YOLOX | **Apache-2.0**（Megvii-BaseDetection YOLOX 官方权重，经 `rknn_model_zoo` 转换） | ✅ |

**除它以外没有任何模型进入安装包。**

### 3.2 明确不随包分发的模型

以下模型的**上游权重**许可不允许我们闭源分发，因此**永不打进 `.deb`**，只在厂商内部用于效果对比：

| 权重来源 | 上游许可 | 为什么不打包 |
|---|---|---|
| Ultralytics YOLOv8 / YOLO11 / YOLO26 系列 | **AGPL-3.0**（官方许可 FAQ：训练代码与其产出的权重都受 AGPL 约束） | 打包分发会连带分发 AGPL 权重，闭源商业网关无法满足其"提供完整对应源码"义务 |
| 各类数据集训练出的第三方权重（CC BY / 非商用研究许可 / 商用需购买） | 逐个不同 | 未核实许可来源的权重一律不进交付包 |

> 说明：`rknn_model_zoo` 等转换/示例仓库本身是 Apache-2.0，但**代码许可不覆盖上游权重**。
> 每次发布前厂商会跑自动化许可审计，任何 FAIL 都不出包。

### 3.3 客户自带模型（BYOM）：运行时加载，我们不重新分发

- 控制台「模型」页可上传客户自己的 `.rknn` 权重 + 类名清单，落盘在设备的可写目录，升级不覆盖、不进入任何安装包。
- 支持的模型家族（按输出形态判定）：**YOLOX、YOLOv8、YOLO26**；`PP-YOLOE` 规划在后续版本；
  **YOLOv5 明确不支持**（锚框 + objectness 与现有解码头差异过大）。
- **权重许可由客户自行确认并承担**：使用 Ultralytics 系产品训练出的权重默认是 AGPL-3.0 / GPL-3.0，
  商用需向权重上游取得授权。我们在模型上传流程里要求客户**声明**许可标识与来源，
  这是为了留痕，**不构成**对客户的许可担保。
- 每条通道硬性只允许 **1 个检测器**（可另加不超过 2 个二级识别器），这是产品约束，也便于许可追溯。

### 3.4 训练与模型转换工具

模型训练框架（如 Ultralytics）、转换工具链（RKNN Toolkit2 等）**不随设备分发**，只在厂商/客户的开发机上使用。

## 4. 其它合规要点

| 项 | 口径 |
|---|---|
| 商标 | "Rockchip""RK3588"等商标归各自权利人所有，仅作兼容性描述使用；产品界面文案默认不出现厂商与芯片名称。 |
| 隐私与数据 | 画面、录像、事件均存在客户本地设备；未启用外部集成（MQTT / HTTP / 对象存储）时不发生任何对外上传。授权校验为**离线**验签，不联网、不上传设备身份。 |
| 日志 | 运行日志为 `key=value` 英文字段，不含账号口令与图片内容。 |
| 安全 | 控制台仅建议内网访问；自签证书、强制首登改密、按能力位授权；固件升级不覆盖客户配置与数据。 |
| 出口管制 | 本产品不含有加密传输以外的受管制密码学功能（授权校验使用 Ed25519 签名）。 |
